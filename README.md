# 工业配电柜三相温差热点预警系统

[![Firmware CI](https://github.com/kusadact/STM32-TriPhaseWatch/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/kusadact/STM32-TriPhaseWatch/actions/workflows/ci.yml)

基于 STM32F407ZGT6 的低压配电柜母排接触热点与温差监测固件。

三路 DS18B20 探头分别贴在配电柜 A、B、C 三相母排的连接处，持续采集三相温度。主机在板端计算相间温差、温升速率和绝对温度，按三级门限判断热点风险，超限时用蜂鸣器和 LED 分级报警。板端带一个事件黑匣子：告警前后的完整过程都写进 SD 卡（触发前 10 秒、告警期间每秒一条、恢复后 30 秒），事后可以回放。对外提供标准 Modbus RTU 从站接口，上位机或 PLC 可以直接读取状态、修改配置。

> **说明**：本项目为实验验证原型，在低压安全条件下测试，严禁直接接触高压带电母排。

---

## 主要功能

- **三相测温**：3 路探头共用 PG9 单总线，按探头 64 位 ROM 地址静态绑定 A/B/C 相，避免总线枚举顺序变化导致测点串位。
- **故障隔离**：单相探头掉线或读数异常时报 `SENSOR_FAULT`，其余两相继续监测，异常相不参与温差与温升计算。
- **分级告警**：支持 NOTICE（提示）、WARNING（警告）、CRITICAL（严重）三级告警；连续 3 次采样超限触发，连续 5 次低于门限（含 2 °C 滞回）恢复。
- **消音与升级**：支持上位机消音（ACK）；消音后仅静音蜂鸣器，LED 保持当前告警状态；若告警在同一事件内升级，沿用原事件 ID 并恢复鸣叫。
- **黑匣子记录**：告警触发时，自动保存触发前 10 秒（环形缓冲）、告警期间（1 秒/条）及恢复后 30 秒的完整过程到 SD 卡；日常按设定周期（默认 30 秒）记录。
- **参数保存**：阈值、记录周期、探头 ROM 绑定关系保存在板载 AT24C02 EEPROM，掉电不丢失。

## 硬件连接

| 功能 | 引脚 / 位置 | 说明 |
| :--- | :--- | :--- |
| **DS18B20 总线** | `PG9` (1WIRE_DQ) | 并联 3 路探头；板载已有 4.7 kΩ 上拉电阻，探头模块无需重复接上拉 |
| **蜂鸣器** | `PF8` | 有源蜂鸣器驱动 |
| **LED 指示** | `PF9` (LED0) / `PF10` (LED1) | 红/绿状态指示灯 |
| **EEPROM** | `PB8` (SCL) / `PB9` (SDA) | 板载 AT24C02，软件 I2C |
| **SD 卡座** | `PC8..PC12`, `PD2` | 直接使用板载 MicroSD 卡槽，软件 SPI 驱动，无需外接 SPI 模块 |
| **RS-485 接口** | `PA2` (TX), `PA3` (RX), `PG8` (RE/DE) | 对应板载 SP3485；跳线 P9 需插在 RS-485 侧（短接 3-5、4-6） |
| **调试串口** | `PA9` (TX), `PA10` (RX) | USART1，115200 8N1，用于系统运行日志输出 |

> **注**：项目另含一份板 B 桥接固件，可在上位机无 USB-RS485 适配器时使用，作为 PC USB 与板 A 之间的透明串口转换。

## 告警规则与声光逻辑

### 1. 默认告警门限

| 判定项目 | NOTICE | WARNING | CRITICAL | 说明 |
| :--- | :---: | :---: | :---: | :--- |
| **绝对温度** | 50 °C | 55 °C | 75 °C | 单相绝对发热水平 |
| **相间最大温差** | 5 °C | 10 °C | 15 °C | 相间负载不平衡或单相接触劣化 |
| **温升速率** | 5 °C/min | 10 °C/min | 20 °C/min | 突发异常温升捕捉 |

### 2. 声光输出节奏

| 状态 | 蜂鸣器 | LED 指示 |
| :--- | :--- | :--- |
| **NORMAL** | 关闭 | 全部熄灭 |
| **NOTICE** | 单次短鸣 100 ms | 不点亮 |
| **WARNING** | 双短鸣（150ms 鸣 / 150ms 停），每 3 秒重复 | LED0 以 500 ms 周期闪烁 |
| **CRITICAL** | 长鸣 500 ms、间隔 250 ms 重复 | LED0 / LED1 以 250 ms 周期同步闪烁 |
| **SENSOR_FAULT** | 双短鸣（100ms 鸣 / 100ms 停），每 5 秒重复 | LED1 以 1 秒周期闪烁 |

## Modbus RTU 接口

- 链路参数：RS-485，9600 bit/s，8E1（8 位数据，偶校验，1 位停止位）。
- 支持功能码：`03`（读保持）、`04`（读输入）、`06`（写单保持）、`10`（写多保持）。

### 常用寄存器简表

| 类型 | 地址 (Hex) | 字段 | 单位 / 说明 |
| :--- | :--- | :--- | :--- |
| **输入寄存器 (04)** | `0x00B0–0x00C7` | DS18B20 快照块 | `0x00B0` 版本、`0x00B1` 源类型、`0x00B2` 有效位、`0x00B3–0x00B4` 采样号、`0x00B5–0x00B7` A/B/C 温度、`0x00B8–0x00BA` 质量码、`0x00BB–0x00BD` 错误码 |
| | `0x00B5–0x00B7` | A / B / C 相实时温度 | 有符号定点数，分辨率 `1/16 °C`（数值除以 16 为实际温度） |
| | `0x00B8–0x00BA` | 三相探头质量码 | 1=正常, 2=超时, 3=CRC 错误, 4=超量程, 5=旧值, 6=未接入 |
| | `0x00C8–0x00E4` | 三相告警快照块 | `0x00C8` 版本、`0x00C9` 等级、`0x00CA` 原因、`0x00CB` 标志位、`0x00CC` 触发相、`0x00CD` 温差有效、`0x00CE` 最大温差、`0x00CF` 最高温、`0x00D0` 最高温相、`0x00D1–0x00D3` 三相温度、`0x00D4–0x00D6` 三相质量、`0x00D7–0x00D8` 事件号、`0x00D9–0x00DA` 采样号、`0x00DB–0x00DC` 持续秒数、`0x00DD–0x00E2` 各级告警计数 |
| | `0x00C9` | 当前告警等级 | 0=NORMAL, 1=NOTICE, 2=WARNING, 3=CRITICAL, 4=SENSOR_FAULT |
| **保持寄存器 (03/06/10)** | `0x0000` | 采集周期 (秒) | 默认 30，允许范围 10 ~ 3600 |
| | `0x0050` | 告警阈值配置块 | `0x0050` 版本；`0x0051–0x0053` 绝对温度三档门限；`0x0054–0x0056` 相间温差；`0x0057–0x0059` 温升速率；`0x005A` 确认次数；`0x005B` 恢复次数；`0x005C` 滞回；`0x005D` 蜂鸣器使能 |
| | `0x0040` | 命令寄存器 | 连写 3 个寄存器：`[命令码, 命令号高 16 位, 命令号低 16 位]`；命令码 1=应用配置, 2=保存配置, 3=启动采集, 4=停止采集, 5=单次采集, 6=校时, 7=预约启动, 8=消音确认 |

## 上位机工具

工具均在 `tools/` 目录，基于 Python 标准库实现，无需通过 pip 安装第三方依赖。

### 1. 命令行工具 (CLI)

```bash
# 查看帮助
python3 tools/modbus_cli.py --help

# 读取三相温度与探头状态
python3 tools/modbus_cli.py --port <串口设备> snapshot

# 查看告警状态、触发相与事件号
python3 tools/modbus_cli.py --port <串口设备> storage-status
```

消音确认（ACK）在图形界面上提供；需要从命令行发送时，按命令寄存器格式向
`0x0040` 连写 `[8, 命令号高 16 位, 命令号低 16 位]`。

### 2. 监控界面 (GUI)

基于 Tkinter，提供三相温度曲线、实时温差、告警指示与配置面板：

```bash
python3 -m tools.modbus_gui
```

## 编译与测试

需要安装 `arm-none-eabi-gcc` 工具链。

### 固件编译

```bash
# 编译监测主机固件（生成 build/board_a/board_a.bin）
./firmware/build/build_board_a.sh

# 编译桥接板固件（生成 build/board_b/buscomm_board_b.bin）
./firmware/build/build_board_b.sh
```

### 自动化测试

项目包含无需硬件的 PC 端纯 C / Python 自动化测试套件：

```bash
# 运行全部宿主机测试与固件编译验证
./tests/host/p7/run_tests.sh
```

测试覆盖告警状态机判定、声光时序、环形事件缓冲、探头故障注入、EEPROM 配置校验及 Modbus 协议编解码。

## 已验证

- **主机测试与固件构建**：`tests/host/p7/run_tests.sh` 全流程通过，覆盖三相告警状态机与阈值、声光输出时间线、预触发/后触发事件缓冲、DS18B20 与探头管理、配置持久化、FreeRTOS 集成、Modbus 协议编解码以及 CLI/GUI；监测板与桥接板固件均构建通过。
- **三相采集**：室温下 A/B/C 三路探头稳定显示，ROM 绑定关系固定，温度按 `1/16 °C` 传输。
- **探头拔插**：拔掉任一探头时对应相报 `SENSOR_FAULT`，其余两相继续显示，插回后恢复正常。
- **分级告警与声光**：注入阈值后触发绝对过温和相间温差告警，蜂鸣器与 LED 按等级动作，现场确认有声光。
- **消音**：`ACK` 后蜂鸣器静音，告警状态与事件号保持，LED 仍按当前等级显示。
- **事件与复位恢复**：告警期间事件写入 SD 卡，停止采集后队列排空；复位后配置、探头绑定和事件标记恢复。
- **存储与链路异常**：SD 卡拔出时告警状态保持、队列积压与错误计数可见，插回后恢复并追赶同步；断开 RS485 链路后上位机读取超时，恢复接线后可继续读到同一告警事件。
